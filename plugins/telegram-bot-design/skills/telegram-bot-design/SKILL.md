# Дизайн-код Telegram-ботов

Единый визуальный стандарт для ВСЕХ наших Telegram-ботов (aiogram 3.x, parse_mode=HTML).
Применяй его при создании или правке любого интерфейса бота: хендлеров, клавиатур,
текстов сообщений, меню. Сверяйся с официальным changelog Bot API:
https://core.telegram.org/bots/api-changelog

## Когда применять

- Создаёшь новый бот / новый раздел / новую команду.
- Правишь текст сообщения, клавиатуру, меню, карточку.
- ПЕРЕД каждым `git commit` / `git push` изменений интерфейса — прогнать проверку
  соответствия (раздел «Проверка перед коммитом» ниже). Это обязательный шаг.

## 1. Кастом-эмодзи (только при Premium у владельца бота)

Пак — **строго** `tgiosicons` (https://t.me/addemoji/tgiosicons). Другие паки не мешать.

Правила:
- Кастом-эмодзи ставятся ТОЛЬКО: **(а) на inline-кнопках**, **(б) на reply-кнопках**
  (`KeyboardButton` тоже поддерживает `icon_custom_emoji_id` — декорировать и их, напр.
  кнопку «Меню»), **(в) в заголовках разделов**. Больше нигде.
- **Запрет на эмодзи в каждой строке** текста. Тело сообщения — без эмодзи построчно
  (никаких «📌 строка / 📍 строка / 💬 строка»). Эмодзи — акцент заголовка/кнопки, не декор.
- **Статус-эмодзи (🟢 🔴 🟠) и предупреждения (⚠️) в ТЕКСТЕ не ставить.** Статус выражать
  словом (LIVE / Бан / Таймаут) либо кастом-иконкой на кнопке; предупреждение/пояснение —
  ЦИТАТОЙ без эмодзи (п.2). Старые плоские эмодзи в метках заменять на пак `tgiosicons`.
- **Единый пак — ОДИН словарь на весь бот** (заголовки И кнопки), чтобы они не расходились.
  Любой новый эмодзи в метке/заголовке → добавить в словарь (прямой id из пака или близкий
  аналог). Статус-кружки 🟢🔴🟠⚪ мапить на иконки пака ПО СМЫСЛУ (✅ активно / 🚫 бан /
  ⏳ ожидание / 🔘 неизвестно) — монохромный пак не даёт цветных кругов. Периодически
  прогонять аудит: все эмодзи в метках/заголовках должны быть в словаре (иначе плоские).
- **Декорируешь reply-кнопку — фильтр её нажатия матчь по тексту БЕЗ ведущего эмодзи**
  (middleware срезает эмодзи метки → пользователь присылает текст без него).
- Кастом-эмодзи доступны, ТОЛЬКО если у владельца бота есть Telegram Premium. Нет
  Premium → обычные Unicode-эмодзи (тогда `icon_custom_emoji_id` НЕ ставить — API
  отклонит запрос). Поэтому декорацию кастом-иконок включать по флагу `premium`.

### Как ставятся (Bot API 9.4, поле `icon_custom_emoji_id`)

Кнопка: кастом-эмодзи — отдельным полем `icon_custom_emoji_id`, НЕ через текст.
Заголовок: кастом-эмодзи в тексте через HTML-тег `<tg-emoji emoji-id="ID">base</tg-emoji>`.

```python
# Заголовок раздела с кастом-эмодзи (в тексте):
#   <tg-emoji emoji-id="6036...">📊</tg-emoji> <b>Статистика</b>
# Кнопка с кастом-иконкой (отдельное поле):
InlineKeyboardButton(text="Рассылка", callback_data="x",
                     icon_custom_emoji_id="6039450962865688331")
```

Получить id иконок пака:
```python
st = await bot.get_sticker_set("tgiosicons")   # 399 иконок
mapping = {s.emoji: s.custom_emoji_id for s in st.stickers}
```

### Рекомендуемая реализация — центральная middleware

Чтобы не трогать сотни мест создания кнопок, подмена делается ЦЕНТРАЛЬНО — исходящей
middleware сессии бота: если текст кнопки начинается с Unicode-эмодзи, у которого есть
иконка в паке, эмодзи убирается из текста, а на кнопку ставится `icon_custom_emoji_id`.
Трогать ТОЛЬКО чистые callback-кнопки (url/web_app/pay/login/switch пропускать — иначе
Telegram может отклонить отправку всей клавиатуры).

```python
from aiogram.client.session.middlewares.base import BaseRequestMiddleware
from aiogram.types import InlineKeyboardMarkup, InlineKeyboardButton

_ICON = {"📨": "6039450962865688331", "📝": "5920046907782074235", ...}  # наш эмодзи → id пака

class ButtonIconMiddleware(BaseRequestMiddleware):
    async def __call__(self, make_request, bot, method):
        rm = getattr(method, "reply_markup", None)
        if isinstance(rm, InlineKeyboardMarkup):
            method = method.model_copy(update={"reply_markup": _decorate(rm)})
        return await make_request(bot, method)

# bot.session.middleware(ButtonIconMiddleware())   # включать только при Premium
```

В заголовках — хелпер `section()` (см. п.2), который оборачивает эмодзи в `<tg-emoji>`.

## 2. Текст сообщений: жирный / моно / цитата

Единственный источник форматирования — хелперы (не писать сырые теги в хендлерах):

| Что | Оформление | Хелпер |
|---|---|---|
| Статичный текст (подписи, лейблы, инструкции) | **жирный** `<b>` | `b("текст")` |
| Переменные (id, токены, номера, суммы, ответы API) | `моно` `<code>` | `mono(value)` |
| Пояснение раздела | `цитата` `<blockquote>` | `quote("текст")` |
| Заголовок раздела (единственное место эмодзи в тексте) | эмодзи + жирный | `section("📊", "Статистика")` |
| Строка «Лейбл: значение» | жирный лейбл + моно значение | `kv("Баланс", "12.30$")` |

```python
from html import escape

def b(text):      return f"<b>{escape(text)}</b>"
def mono(v):      return f"<code>{escape(str(v))}</code>"
def quote(text, expandable=False):
    tag = "<blockquote expandable>" if expandable else "<blockquote>"
    return f"{tag}{escape(text)}</blockquote>"
def kv(label, v): return f"{b(label)}: {mono(v)}"
def section(emoji, title):   # эмодзи рендерится как кастом (<tg-emoji>) при Premium
    return f"{_emoji_html(emoji)} <b>{escape(title)}</b>"
```

### Пример правильного сообщения раздела

```python
text = "\n\n".join([
    section("🔑", "Доступ к профилю"),
    quote("Выдайте клиенту доступ к профилю на срок с суточным лимитом. "
          "Ограниченный доступ видит только свои диалоги."),
    kv("Профиль", prof.label),
    kv("Номер", prof.phone),
    kv("Лимит в сутки", limit),
])
```

Так: заголовок — с эмодзи-акцентом; пояснение — цитатой; данные — `Лейбл: моно-значение`.
НЕ ставить эмодзи в строках `kv(...)` и не делать весь текст жирным/моно сплошняком.

### Древовидный визуал блоков (┏ / ┣ / ┗) — TASK622

Списки параметров в тексте оформляй ДЕРЕВОМ: первая строка блока — `┏` (или `┣`,
если прямо над блоком есть заголовок `section(...)`), средние — `┣`, последняя — `┗`.
Группы разделяй пустой строкой; у каждой группы свой `┗` в конце.

```python
def tree(items, first="┏"):
    out = []
    for i, line in enumerate(items):
        pre = "┗" if i == len(items) - 1 else (first if i == 0 else "┣")
        out.append(f"{pre} {line}")
    return out

text = "\n".join([
    section("⚙️", "Настройки"), "",
    section("☁️", "Экспорт в Google-таблицу"),
    *tree([kv("Таблица", "Установлена"),
           kv("Сервисный аккаунт", email)], first="┣"),   # под заголовком → ┣…┗
    "",
    *tree([kv("Чат уведомлений", chat),
           kv("Скорость отправки", "5 сообщ/сек"),
           kv("Автоперевод", "По запросу")], first="┏"),   # самостоятельный блок → ┏…┗
])
```

Правило: один блок = одно дерево; длинные значения (URL/токены) — короткий статус
(«Установлена»), не полный URL.

## 3. Таблицы (rich-сообщения) — там, где уместно

> **ПРЕСЕТ (правило вызова).** Любой запрос вида «сделай таблицу в разделе X» /
> «покажи это таблицей» → НЕ изобретай формат заново: возьми **готовый модуль-пресет
> ниже** (`bot/services/rich.py`), положи его в проект (если ещё нет) и вызови его
> функции. Все правила формата (зебра off, параметры жирный / значения моно, обе
> колонки слева, кастом-эмодзи в heading, статусы вместо длинных значений, цитата-
> подсказка) уже зашиты в пресет — на всех таблицах проекта формат будет одинаковым.

**Готовый пресет — скопировать в `bot/services/rich.py`:**

```python
from aiogram import Bot
from aiogram.types import (InputRichMessage, InputRichBlockSectionHeading,
    InputRichBlockTable, RichBlockTableCell, RichTextBold, RichTextCode,
    RichTextCustomEmoji, InputRichBlockParagraph, InputRichBlockBlockQuotation,
    InlineKeyboardMarkup)
from bot.utils.tgicons import ICONS as _PACK        # эмодзи → custom_emoji_id пака
_NORM = {k.replace("️", "").replace("⃣", ""): v for k, v in _PACK.items()}

def _cid(e): return _NORM.get((e or "").replace("️", "").replace("⃣", ""))

def _emoji(e, label):                                 # [кастом-иконка, " текст"] | текст
    cid = _cid(e) if e else None
    return [RichTextCustomEmoji(custom_emoji_id=cid, alternative_text=e), " " + str(label)] \
        if cid else (f"{e} {label}" if e else str(label))

def heading(text, size=1, emoji=None):
    return InputRichBlockSectionHeading(text=_emoji(emoji, text), size=size)

def quote_block(text):                                # подсказка-цитата снизу
    return InputRichBlockBlockQuotation(blocks=[InputRichBlockParagraph(text=str(text))])

def kv_table(rows):                                   # (параметр, значение) — ЕДИНЫЙ вид
    cells = [[RichBlockTableCell(align="left", valign="middle", text=RichTextBold(text=str(k))),
              RichBlockTableCell(align="left", valign="middle", text=RichTextCode(text=str(v)))]
             for k, v in rows]
    return InputRichBlockTable(cells=cells, is_bordered=False, is_striped=False)  # зебра/рамки OFF

async def send_rich(bot: Bot, chat_id, blocks, reply_markup: InlineKeyboardMarkup | None = None):
    return await bot.send_rich_message(chat_id=chat_id,
        rich_message=InputRichMessage(blocks=blocks), reply_markup=reply_markup)
```

**Вызов (так во ВСЕХ разделах — один формат):**

```python
await send_rich(bot, chat_id, [
    heading("Настройки", emoji="⚙️"),             # кастом-иконка в заголовке
    kv_table([("Google-таблица", "установлена"),  # длинные URL/токены → короткий статус
              ("Скорость отправки", "15 сообщ/сек")]),
    quote_block("Подсказка снизу — цитатой."),
], reply_markup=markup)
```

Для данных (статистика, сводки, списки с колонками) используй **таблицы** Bot API
(rich-сообщения `sendRichMessage` + `InputRichMessage.blocks`, Bot API 10.1/10.2),
а не моноширинный «псевдо-ASCII». Таблица поддерживает `reply_markup` — шлётся с кнопками.

**Важно (архитектура):** rich-сообщение — ОТДЕЛЬНОЕ сообщение, его НЕЛЬЗЯ редактировать
на месте как обычные edit-навигируемые меню. Есть два пути:
- **Самостоятельное сообщение** со своей кнопкой «Закрыть» (удаляет сообщение) — для
  разовых сводок (статистика профиля/рассылки).
- **Раздел целиком таблицей** (напр. ⚙️ Настройки): раз rich не редактируется, навигация
  строится на **«удалить + прислать заново»** — вход/«Назад» рисуют свежую таблицу,
  тумблеры перерисовывают её, под-экраны затирают таблицу и возвращают по «Назад».
  Полезно дать переключатель **«Вид: Таблица / Текст»** (дефолт — Таблица) первой кнопкой
  (над «Информацией»): вид хранится per-user, Текст = обычный экран с `section()`/`kv()`.

**Формат таблиц (ПОДТВЕРЖДЁННЫЙ дизайн-код, строго):**
- **Зебра ВЫКЛЮЧЕНА** (`is_striped=False`) ВСЕГДА. Чередование фона читается как
  чередование шапок — будто каждая вторая строка заголовок.
- **Рамки и компактность — по вкусу** (`is_bordered`, `is_compact`). Для раздела-настроек
  подтверждён вид БЕЗ рамок и БЕЗ компактности (чистый список).
- **Двухколоночная kv-таблица (Параметр | Значение):** строки-шапки ВНУТРИ НЕТ (её роль
  выполняет `heading` сверху); **параметры — ЖИРНЫЙ** (`RichTextBold`), **значения — МОНО**
  (`RichTextCode`); **обе колонки по ЛЕВОМУ краю** (`align="left"`).
- **Кастом-эмодзи В `heading` И В ЯЧЕЙКАХ РАБОТАЮТ** (подтверждено живым примером): текст
  блока — СПИСОК `[RichTextCustomEmoji(custom_emoji_id, alternative_text), " текст"]`.
  Плейн-строка как элемент списка допустима. Нормализуй селектор U+FE0F при поиске id в
  паке. (Прежнее «ломает отправку» — НЕВЕРНО, то была другая причина.)
- **Длинные значения (URL/email/токены) в таблицу НЕ класть** — короткий статус:
  «установлена» / «не задана», «установлен» / «не настроен»; полное — в под-экране.
- **Блок-цитата** в rich — `InputRichBlockBlockQuotation(blocks=[InputRichBlockParagraph(...)])`
  (у цитаты нет своего `text`, только вложенные блоки): удобна для подсказки снизу.

```python
from aiogram.types import (InputRichMessage, InputRichBlockSectionHeading,
    InputRichBlockTable, RichBlockTableCell, RichTextBold, RichTextCode,
    RichTextCustomEmoji, InputRichBlockBlockQuotation, InputRichBlockParagraph)

GEAR = "5904258298764334001"   # id иконки ⚙️ из пака (пример)

def cell(t, *, bold=False, code=False):
    s = "" if t is None else str(t)
    rt = RichTextBold(text=s) if bold else RichTextCode(text=s) if code else s
    return RichBlockTableCell(align="left", valign="middle", text=rt)  # обе колонки слева

table = InputRichBlockTable(cells=[            # зебра OFF, рамок нет
    [cell("Google-таблица", bold=True), cell("установлена", code=True)],
    [cell("Скорость отправки", bold=True), cell("15 сообщ/сек", code=True)],
], is_bordered=False, is_striped=False)

await bot.send_rich_message(chat_id=chat_id, rich_message=InputRichMessage(blocks=[
    # кастом-эмодзи в заголовке РАБОТАЕТ — список [эмодзи, " текст"]
    InputRichBlockSectionHeading(text=[
        RichTextCustomEmoji(custom_emoji_id=GEAR, alternative_text="⚙️"), " Настройки"], size=1),
    table,
    InputRichBlockBlockQuotation(blocks=[InputRichBlockParagraph(
        text="Подсказка снизу — цитатой.")]),
]), reply_markup=markup)
```

Уместно: статистика профиля/рассылки, сводки, раздел настроек. Не уместно: интерактивные
меню с частой навигацией, где нужна редактируемость на месте (их оставляем на inline-
клавиатурах с edit-навигацией — либо строим на «удалить + прислать заново»).

## 4. Цвет кнопок — ТОЛЬКО на важные (Bot API 9.4, поле `style`)

Разрешены РОВНО три значения (прочее API отклоняет: «Invalid button style specified»):

| Цвет | `style` | Для чего (важные акценты) |
|---|---|---|
| 🔵 Синий | `primary` | главный старт — например «Запустить рассылку» |
| 🟢 Зелёный | `success` | деньги/приход — например «Пополнить баланс» |
| 🔴 Красный | `danger` | стоп/прерывание — например «Остановить рассылку» |

Правило: цвет — **акцент на ключевое действие**, а не раскраска всего. Обычные
«Удалить / Подтвердить / Назад» остаются нейтральными. Один цветной акцент на экран.

```python
InlineKeyboardButton(text="Запустить рассылку", callback_data="go", style="primary")
InlineKeyboardButton(text="Пополнить баланс",   callback_data="up", style="success")
InlineKeyboardButton(text="Остановить",          callback_data="st", style="danger")
```

Можно раскатать через ту же `ButtonIconMiddleware` по узкому списку важных действий
(substring по очищенному тексту метки), не перетирая явно заданный `style`.

**Осторожно с подстроками — красить только ТОЧНЫЕ действия.** Напр. «Стоп при лимите»
(тумблер-настройка) НЕ должен быть danger: substring «стоп» ловит его ложно. danger —
только реальная остановка («Остановить/Прервать рассылку»). Проверяй, что цвет не прилип
к настройке/навигации.

---

## 4.1. Словарь действий → иконка (пак tgiosicons) + цвет

Единая семантика: одинаковые действия во ВСЕХ разделах оформляются одинаково — одной
иконкой пака и одним цветом. Иконка ставится как ведущий эмодзи метки (middleware меняет
его на `icon_custom_emoji_id`), цвет — поле `style` только у важных действий.

Пак `tgiosicons` = **399 РАЗНЫХ иконок** (у каждой свой `custom_emoji_id`); запасных
эмодзи-fallback всего 173 (до 16 иконок делят один fallback). Поэтому иконку под действие
подбирают по РЕАЛЬНОМУ изображению (визуальный каталог пака — скачать превью стикеров и
посмотреть), а НЕ только по запасному эмодзи — иначе возьмётся не та из «одноэмодзийных».
Пары ниже — проверенные по изображению (напр. Пополнить → кошелёк, Запустить → play,
Рассылка → рупор, Оформление → кисть, Полный доступ → корона).

**Цвет (style) — по смыслу:**
- 🟢 `success` (зелёный): деньги/приход — **Пополнить баланс**, Оплатить, Подтвердить оплату.
- 🔵 `primary` (синий): главный старт — **Запустить рассылку**, Отправить рассылку, Начать.
- 🔴 `danger` (красный): остановка/прерывание/необратимое — **Остановить / Прервать рассылку**.
- нейтральные (без цвета): навигация, тумблеры, обычные действия (Удалить/Подтвердить/Назад).

**Иконка (эмодзи-ключ пака) — по действию:**

| Действие / смысл | Эмодзи | Цвет |
|---|---|---|
| Пополнить баланс / оплата | 💰 (или 💳 карта) | 🟢 success |
| Баланс / кошелёк | 👛 | — |
| Запустить / начать (рассылку) | ▶ (play) | 🔵 primary |
| Отправить | 📤 | 🔵 primary (если старт) |

**Как применять ко всем разделам — ЦЕНТРАЛЬНО, не правя сотни кнопок:** в `ButtonIconMiddleware`
иконка определяется по КЛЮЧЕВОМУ СЛОВУ в начале метки (`startswith` по очищенному тексту,
упорядоченный словарь `_ICON_RULES` действие→эмодзи), иначе — по ведущему эмодзи метки. Так
«Запустить рассылку»→play, «Пополнить»→кошелёк, «Удалить…»→корзина, «Отменить»→крестик во ВСЁМ
боте автоматически. Правила: специфичное ПЕРЕД общим (напр. «запустить рассыл» выше «рассылк»);
`startswith`, а не `in` (чтобы «Включить» не поймалось на «ключ»); все эмодзи — в `ICONS`.
**Нормализация вариационного селектора (грабли):** значения в `_ICON_RULES` могут содержать
селектор U+FE0F (напр. «⚙️», «⏸️»), а ключи пака хранятся БЕЗ него. Перед поиском id в
словаре ключ нужно нормализовать (`.replace("️","").replace("⃣","")`), иначе иконка
не подставится и кнопка останется с ПЛОСКИМ эмодзи (типовой баг «Настройки»).
**Проверка словаря:** прогнать его по ВСЕМ меткам кнопок кода (извлечь `text=…` регуляркой) и
просмотреть пары текст→иконка на ложные совпадения ДО деплоя. Один смысл → одна иконка; цвет —
только у трёх важных действий.

## 5. Анти-флуд (в целом, не только /menu)

Принцип: бот не плодит сообщения и не захлёбывается кликами. Покрывает ВСЕ источники флуда:

1. **Клики по кнопкам (callback-спам):** middleware-троттлинг — лок на пользователя +
   cooldown (гасит серию быстрых нажатий, очередь устаревших не копится). Всегда
   `callback.answer()` (гасит «часики»), без лишних сообщений в ответ на клик.
2. **Навигация по разделам:** правка НА МЕСТЕ (`edit_text`/`edit_caption`), а не новое
   сообщение на каждый шаг. Открытие под-раздела ЗАМЕНЯЕТ родительский экран (напр.
   «Профили» → «Номер» — список профилей должен исчезнуть/перерисоваться, а не остаться
   висеть). «Назад» редактирует то же сообщение. Нередактируемое (фото) — `delete` родителя
   + `answer` нового, а не два сообщения.
3. **Удалять ВВОД пользователя:** саму команду (`/start`, `/menu`) И нажатие reply-кнопки
   (напр. «Меню» — это обычное текстовое сообщение от пользователя, его тоже `delete`).
   Для команд, создающих новое сообщение: хранить id последнего такого сообщения на чат →
   удалять предыдущее перед отправкой нового; служебные уведомления не дублировать.
4. **Прогресс / многошаговые отчёты:** обновлять ОДНО статус-сообщение (`edit_text`), а не
   слать новое на каждый шаг; троттлить правки (Telegram: ~1 правка/сек; в группах ~20
   сообщений/мин — ловить `TelegramRetryAfter`).
5. **Групповые уведомления (карточки вебхуков, логи):** не постить на КАЖДОЕ событие —
   дедуп/тред: одна карточка на клиента, повторы — реплаем на неё или только в историю;
   смена статуса — правкой той же карточки (галочка), а не новым сообщением.
6. **Массовые отправки в чат:** не слать в цикле по элементу; сводить/батчить; уважать
   лимиты Telegram, обрабатывать `TelegramRetryAfter` (не ретраить вслепую).
7. **Глобальная отмена любого флоу:** на ЛЮБОМ незавершённом этапе (ввод текста, чатов,
   ключей, подтверждения) `/start`·`/menu`·`/cancel`·reply-«Меню»·слово «Отмена» должны
   сбрасывать FSM и возвращать в меню. Для этого роутер меню подключать ПЕРВЫМ (до
   роутеров с FSM-состояниями), а его хендлеры — БЕЗ `StateFilter` (тогда ловят в любом
   состоянии и имеют приоритет). Иначе FSM-хендлер перехватит `/start` как ввод (напр.
   запишет «/start» текстом рассылки).

Пример (пункт 3 — команда `/menu` затирает прошлое меню):

```python
_last_menu: dict[int, int] = {}   # chat_id → message_id

async def send_menu(message, ...):
    chat_id = message.chat.id
    prev = _last_menu.pop(chat_id, None)
    if prev:
        try: await message.bot.delete_message(chat_id, prev)
        except Exception: pass
    sent = await message.answer_photo(...)   # или answer(...)
    _last_menu[chat_id] = sent.message_id

@router.message(Command("menu"))
async def cmd_menu(message, ...):
    try: await message.delete()              # убрать саму команду
    except Exception: pass
    await send_menu(message, ...)
```

Если нередактируемое сообщение (фото → текст нельзя edit_text): удалить и отправить
заново (`delete` + `answer`), а не плодить.

## 6. Проверка перед коммитом (ОБЯЗАТЕЛЬНО)

После КАЖДОГО обновления раздела или добавления функции — ПЕРЕД `git commit`/`git push`
прогнать изменённый код по чек-листу и явно подтвердить соответствие (или починить).
Не коммить, пока все пункты не ✅.

Чек-лист (по изменённым файлам интерфейса):

1. **Текст**: статика — через `b()`; переменные — через `mono()`/`kv()`; пояснения
   раздела — через `quote()`. Нет сырых `<b>`/`<code>`/`<blockquote>` в хендлерах. Нет
   «голого» текста там, где должен быть жирный/моно.
2. **Заголовок**: ровно один `section("эмодзи","Название")` на экран; эмодзи только в нём.
3. **Эмодзи**: нет эмодзи/статус-значков (🟢 ⚠️) построчно в теле; кастом-эмодзи `tgiosicons`
   только на inline- И reply-кнопках и в заголовках; старые плоские эмодзи заменены на пак;
   при отсутствии Premium — кастом не ставится.
4. **Кнопки — иконка и цвет по словарю (п.4.1)**: один смысл → одна иконка пака во всём
   боте (ведущий эмодзи метки по таблице, не «какой попало»); `style` только у важных
   действий (primary=Запустить, success=Пополнить, danger=Остановить); обычные кнопки
   нейтральны; значения строго primary|success|danger.
5. **Таблицы**: данные-сводки/настройки — rich-таблицей; ЗЕБРА OFF (`is_striped=False`);
   kv — без строки-шапки (заголовок `heading` сверху), параметры жирный / значения моно,
   обе колонки слева; кастом-эмодзи в `heading` И ячейках РАБОТАЮТ (список `[эмодзи,текст]`,
   нормализуй селектор); длинные URL/токены → короткий статус; подсказка снизу — блок-цитата;
   навигация «удалить + прислать заново»; переключатель «Вид: Таблица/Текст» (дефолт Таблица).
6. **Анти-флуд (в целом)**: клики гаснут троттлингом + `callback.answer()`; навигация правит
   сообщение (edit), под-раздел ЗАМЕНЯЕТ родителя; ВВОД пользователя (команда `/start`·`/menu`
   и нажатие reply-кнопки «Меню») удаляется; команды меню затирают прошлое; прогресс — одно
   статус-сообщение; групповые карточки дедуплены/тредом; массовые отправки уважают лимиты;
   глобальная отмена (`/start`·`/menu`·`/cancel`·«Меню»·«Отмена») сбрасывает любой FSM
   (роутер меню ПЕРВЫМ, без `StateFilter`).
7. **callback_data** не менялись без причины; длинные значения в пределах лимитов.
8. Код компилируется и импортируется (`py_compile` + import), бот поднимается без ошибок.

Процедура скана: прочитать diff изменённых хендлеров/клавиатур/текстов; пройтись по 1–8;
перечислить несоответствия; ПОЧИНИТЬ; затем сверить спорные новые поля API с changelog
(ссылка вверху). Только после «все ✅» — commit/push.

Формат вывода проверки (кратко, в ответе пользователю перед коммитом):
```

```
Если что-то ❌ — сначала фикс, потом повтор проверки, и только потом commit/push.
